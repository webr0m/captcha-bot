# AdSense: integración y restricciones

El propietario confirmó que webrom.cc está aprobado en AdSense. Se conserva el cliente `ca-pub-8258058186888619`, la unidad `1577557462`, el formato auto y el ancho responsive del código entregado.

## Decisión final

La petición inicial de alternar cada quince segundos se sustituyó por la instrucción posterior de evitar infracciones de las políticas de Google. No se publica un carrusel ni se programa refresco automático de ningún anuncio. AdSense queda como bloque estático al final del contenido, separado del banner existente y de los controles.

Las políticas consultadas restringen el auto-refresco, el uso de iframes y los entornos de aplicaciones/WebView. La aprobación del dominio no acredita por sí misma la compatibilidad del contenedor de Telegram. Por ello:

- No se solicita el script ni se ejecuta `adsbygoogle.push` si la página se abre dentro de un iframe, recibe initData de Telegram o identifica un WebView en su user agent.
- Esto mantiene AdSense inactivo en los flujos actuales de la Mini App. No se presenta esa integración como monetización aprobada para Telegram.
- El código queda preparado para un navegador compatible de nivel superior, dentro del dominio aprobado. No se añade una salida que transfiera initData a otro navegador ni se elude la autenticación del panel para mostrar publicidad.
- El servidor bloquea AdSense en workers.dev, dominios ajenos, países desconocidos, EEE, Reino Unido y Suiza. No se declara configurada una CMP ni se inventa consentimiento. La restricción regional permanece hasta una integración de consentimiento verificada.
- Cada espacio se inicia una sola vez por apertura. Guardar, abrir secciones o cambiar de grupo no recrea los nodos, no recarga scripts y no vuelve a solicitar anuncios.
- El bloque de Google está en el documento principal; no se introduce en el iframe del otro proveedor. Se mantiene fuera del widget de traducción y se respeta `data-ad-status="unfilled"` sin provocar solicitudes adicionales.
- Se retiran los datos de lanzamiento de la URL después de capturarlos y antes de cargar publicidad. El iframe del proveedor anterior sigue aislado y sin datos de sesión.

La implementación reduce los riesgos identificados; no certifica la aprobación de Google ni el cumplimiento integral de una cuenta, del contenido publicado o de todas las obligaciones de privacidad. Estas condiciones no pueden verificarse únicamente con el código facilitado.

## Validación

129 pruebas locales pasan, incluidas cinco para elegibilidad por dominio/país, bloqueo de Telegram/iframes/WebViews, inicio único sin temporizadores, ausencia de solicitudes en contextos bloqueados y manejo independiente de errores y falta de relleno. Typecheck y empaquetado de Wrangler pasan. No se hacen clics ni se generan solicitudes de prueba a AdSense.
